Every torch.compile commit that landed between 2026-11-15 and 2026-11-22, including the ones the [issue]({{< relref "/posts/2026-11-22-this-week-in-torch-compile" >}}) only counted.

## Dynamo commits
- Fixes torch.compile silently returning the traced device's stream when code calls current_stream() with the index of a different device. ([#201619](https://github.com/pytorch/pytorch/pull/201619), @AAYESLY)
- Speeds up the guard that checks whether mutated inputs still share storage the same way, which compared every pair of views on each cache hit and slowed compiled optimizer steps. ([#205789](https://github.com/pytorch/pytorch/pull/205789), @williamwen42)
- Fixes activation-checkpointing compile failures by never marking graph inputs as must-recompute, since inputs cannot be recomputed. ([#199629](https://github.com/pytorch/pytorch/pull/199629), @0z5a)
- Fixes a guard-creation crash (NameError: SYNTHETIC_LOCAL) when code calls type(), hasattr() or methods on an nn.Parameter created inside the compiled function. ([#205173](https://github.com/pytorch/pytorch/pull/205173), @peterdsharpe)
- Fixes a recent regression where a function that mutates an input and uses an assume_constant_result tensor failed to compile with NameError. ([#205231](https://github.com/pytorch/pytorch/pull/205231), @zlin888)
- Fixes incorrect results when comparing a Tensor or SymInt with an IntEnum, IntFlag or float enum member under torch.compile; == was always False and < caused graph breaks. ([#204573](https://github.com/pytorch/pytorch/pull/204573), @daud4653)
- Adds per-code-object locking around Dynamo's cache metadata to fix races from multithreaded use and torch._dynamo.reset(), especially on free-threaded Python. ([#201685](https://github.com/pytorch/pytorch/pull/201685), @alexmalyshev)
- Dynamo can now trace `del some_global` (the DELETE_GLOBAL bytecode), which used to fail under fullgraph=True or cause a graph break. ([#197056](https://github.com/pytorch/pytorch/pull/197056), @KarhouTam)
- Fixes RecursionError at graph breaks in very long functions by making Dynamo's live-variable analysis and instruction copying non-recursive. ([#204639](https://github.com/pytorch/pytorch/pull/204639), @KasraGhodsi)
- Leaving a config.patch() block now leaves previously unset keys unset instead of overriding them with their defaults, which fixes spurious Dynamo recompiles. ([#205211](https://github.com/pytorch/pytorch/pull/205211), @aorenste)
- Dynamo can now trace bytearray.removeprefix() and bytearray.removesuffix() without a graph break and raises the same errors as CPython. ([#205781](https://github.com/pytorch/pytorch/pull/205781), @Oscar-man-shrestha)
- Dynamo can now trace the eight bytearray predicate methods (isalnum, isalpha, isascii, isdigit, islower, isspace, istitle, isupper). ([#205779](https://github.com/pytorch/pytorch/pull/205779), @Oscar-man-shrestha)
- Under torch.compile, enumerate() on a non-iterable now raises TypeError immediately as Python does, instead of waiting until the result is first iterated. ([#205992](https://github.com/pytorch/pytorch/pull/205992), @anchi205)
- Dynamo can now trace bytearray.strip(), lstrip() and rstrip() with CPython-matching argument checks and errors. ([#205821](https://github.com/pytorch/pytorch/pull/205821), @Oscar-man-shrestha)
- Bytearray.maketrans no longer breaks torch.compile(fullgraph=True) when both arguments are known at trace time. ([#205462](https://github.com/pytorch/pytorch/pull/205462), @frogsterr)
- Dynamo can now trace bytearray.capitalize() and bytearray.swapcase(). ([#205394](https://github.com/pytorch/pytorch/pull/205394), @Oscar-man-shrestha)
- Torch.Stream and torch.Event subclasses created inside a compiled region now keep their subclass type when rebuilt after a graph break, which fixes crashes in backend extensions. ([#188406](https://github.com/pytorch/pytorch/pull/188406), @Stevennnn)
- Dynamo now matches CPython by ignoring ABC-registered virtual subclasses when deciding whether to try a reflected operator such as __radd__ first. ([#205725](https://github.com/pytorch/pytorch/pull/205725), @guilhermeleobas)
- Dynamo can now read a global that was created by an earlier STORE_GLOBAL in the same trace, where it used to raise NameError. ([#205727](https://github.com/pytorch/pytorch/pull/205727), @guilhermeleobas)
- Operator.length_hint on a reversed(list) iterator no longer causes a graph break. ([#205728](https://github.com/pytorch/pytorch/pull/205728), @guilhermeleobas)
- Dynamo's fallback for the `in` operator now checks identity before calling __eq__, as CPython does. ([#205737](https://github.com/pytorch/pytorch/pull/205737), @guilhermeleobas)
- Dynamo now supports dict_items.isdisjoint(), not just dict_keys.isdisjoint(). ([#205738](https://github.com/pytorch/pytorch/pull/205738), @guilhermeleobas)
- Range() with a step of zero now raises ValueError under torch.compile, matching Python. ([#205739](https://github.com/pytorch/pytorch/pull/205739), @guilhermeleobas)
- Int() on an int subclass instance now calls the subclass's own __int__ under torch.compile instead of skipping it. ([#205729](https://github.com/pytorch/pytorch/pull/205729), @guilhermeleobas)
- Dynamo now handles datetime values created during tracing (for example as enum member values) instead of graph-breaking with 'Unexpected type in sourceless builder'. ([#205880](https://github.com/pytorch/pytorch/pull/205880), @guilhermeleobas)
- Selective activation checkpointing (SAC) policies now apply to checkpoint calls inside a scan body under non-strict tracing and eager scan, matching torch.compile. ([#203534](https://github.com/pytorch/pytorch/pull/203534), @jack8558)
- Dynamo can now trace bytearray.zfill() and bytearray.expandtabs() without a graph break. ([#205200](https://github.com/pytorch/pytorch/pull/205200), @0x3ddie)
- Adds training (forward and backward) support for scaled dot-product attention on Intel XPU through the OneDNN backend. ([#162454](https://github.com/pytorch/pytorch/pull/162454), @LuFinch)
- Calls to unbound slot wrappers such as object.__eq__(a, b) now run the descriptor's own C slot as CPython does, instead of picking up a subclass's Python override. ([#203085](https://github.com/pytorch/pytorch/pull/203085), @guilhermeleobas)
- When a generator paused in `yield from` is closed, Dynamo now calls close() on the inner iterator only if it defines one, matching CPython. ([#205696](https://github.com/pytorch/pytorch/pull/205696), @guilhermeleobas)
- A `with` statement on an object without __enter__ or __exit__ now raises TypeError under torch.compile, as CPython does, instead of causing a graph break. ([#205719](https://github.com/pytorch/pytorch/pull/205719), @guilhermeleobas)
- Dynamo can now trace __reduce__ on bytearrays and bytearray iterators. ([#205004](https://github.com/pytorch/pytorch/pull/205004), @losewayy)
- Torch.compile can now deep-copy an OrderedDict, which used to fail on an unsupported item iterator. ([#204199](https://github.com/pytorch/pytorch/pull/204199), @LittlePyx)
- The compiler bisector now reads its saved state with ast.literal_eval instead of eval, so the state file cannot run arbitrary code. ([#205235](https://github.com/pytorch/pytorch/pull/205235), @krastogi-in)
- Fixes wrong qualified function names in Dynamo output when code follows a one-line def or class, such as 'E.f' instead of 'f'. ([#199357](https://github.com/pytorch/pytorch/pull/199357), @Mohit-25-tech)

## Inductor commits
- Inductor now computes floor divisions that depend only on sizes once on the host instead of in every kernel element, which made vLLM's FP8 block-cast kernel about 1.2x faster under dynamic shapes. ([#205053](https://github.com/pytorch/pytorch/pull/205053), @oonyshch)
- Inductor can now generate pointwise and reduction kernels tiled over more than three dimensions when triton.max_tiles is set above 3; the default is unchanged. ([#204324](https://github.com/pytorch/pytorch/pull/204324), @blaine-rister)
- Fixes a race where Inductor's reinplacing pass dropped user CUDA stream annotations from rebuilt scatter ops, so they ran on the default stream and could read stale data. ([#205925](https://github.com/pytorch/pytorch/pull/205925), @ankitgala007)
- Fixes Inductor fusing long scatter chains into a padding kernel that reached about 1% of the memory bandwidth limit on H100 and GB300. ([#204118](https://github.com/pytorch/pytorch/pull/204118), @Roger-ZRZ)
- Flex attention's Triton kernels on AMD MI300/MI350 (gfx942/gfx950) now place blocks of the same batch and head on the same XCC (accelerator complex die) so they share its L2 cache. ([#204453](https://github.com/pytorch/pytorch/pull/204453), @jayfurmanek)
- Fixes symbolic modular-indexing simplifications that could give incorrect index results, and makes them handle more general expressions. ([#200418](https://github.com/pytorch/pytorch/pull/200418), @morrison-turnansky)
- Limits how many dynamic-shape sub-kernels go into one combo kernel, fixing RecursionErrors and compiles of over 30 minutes on large dynamic torch.cat calls. ([#205934](https://github.com/pytorch/pytorch/pull/205934), @anijain2305)
- Adds a max_autotune_reduction config so reduction kernels can get the wider autotuning search separately from pointwise kernels; existing settings are unchanged. ([#205532](https://github.com/pytorch/pytorch/pull/205532), @jhou-jpg)
- Torch.compile on Apple MPS now packs kernel arguments into Metal argument buffers, so heavily fused kernels no longer exceed Metal's buffer-argument limit. ([#202180](https://github.com/pytorch/pytorch/pull/202180), @Arnav66692)
- Adds the reorder_for_peak_memory_preserve_collective_order config so Inductor's peak-memory reordering keeps distributed collectives in their original order, avoiding possible hangs. ([#205256](https://github.com/pytorch/pytorch/pull/205256), @Microve)
- Fixes random NaN outputs from matmul templates with fused prologues by loading masked-off lanes as zero instead of leaving them undefined. ([#205373](https://github.com/pytorch/pytorch/pull/205373), @haowu14)
- Fixes silent wrong results where Inductor reinplaced an op whose result was still in use and a later write to the original input then changed it. ([#205354](https://github.com/pytorch/pytorch/pull/205354), @jyzjameszhang)
- Fixes compiled GPU code crashing with CUDA_ERROR_INVALID_VALUE when Inductor inlined a zero-dimensional CPU expression into a GPU kernel. ([#203407](https://github.com/pytorch/pytorch/pull/203407), @Z-Ghostshell)
- Adds a faster max_pool2d backward decomposition for non-overlapping windows that gathers gradients instead of using scatter_add. ([#195124](https://github.com/pytorch/pytorch/pull/195124), @orrangetabby17)
- Adds backend interfaces so out-of-tree accelerators can reuse CUDA Graph Trees by supplying their own graph and allocator operations. ([#194598](https://github.com/pytorch/pytorch/pull/194598), @luochao-dev)
- Fixes torch.compile on Apple MPS silently computing only part of kernels with 2^32 or more elements because Metal truncated the launch grid. ([#202423](https://github.com/pytorch/pytorch/pull/202423), @aditvenk)
- Adds module_fqns and weight_fqns (fully qualified names of modules and weights) to each kernel in kernel_information.json, so profile costs can be traced to specific model layers. ([#204539](https://github.com/pytorch/pytorch/pull/204539), @MirrorZ)
- The AOTInductor model runtime now supports PrivateUse1 (out-of-tree) devices, so custom backends can load AOTInductor packages. ([#204396](https://github.com/pytorch/pytorch/pull/204396), @can-gaa-hou)

- Fixes Triton compiles in forked compile workers with compile_on_one_rank, which failed because workers queried the CUDA device to choose a Triton cache directory. ([#205618](https://github.com/pytorch/pytorch/pull/205618), @bobrenjc93)

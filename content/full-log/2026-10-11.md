Every torch.compile commit that landed between 2026-10-04 and 2026-10-11, including the ones the [issue]({{< relref "/posts/2026-10-11-this-week-in-torch-compile" >}}) only counted.

## Dynamo commits
- Precompile can now save captures where a graph break happens inside a called function (such as a child module's forward) by writing them as installed-mode artifacts. ([#198523](https://github.com/pytorch/pytorch/pull/198523), @bobrenjc93)
- Dynamo no longer silently drops maxlen when replaying mutations on deque inputs, so bounded deques behave like eager. ([#200528](https://github.com/pytorch/pytorch/pull/200528), @XuehaiPan)
- Fx.traceback.annotate tags are now preserved across graph breaks instead of being lost or failing the frame. ([#198959](https://github.com/pytorch/pytorch/pull/198959), @enlighten5)
- The scan higher-order op now accepts inputs that are views of the same storage (such as K and V from a fused QKV projection) as long as none are mutated. ([#199688](https://github.com/pytorch/pytorch/pull/199688), @bohnstingl)
- Dynamo's has_torch_function now returns True while a TorchFunctionMode is active, so modes see calls following the standard override pattern. ([#196053](https://github.com/pytorch/pytorch/pull/196053), @ezyang)
- Dynamo can now trace torch.overrides.handle_torch_function, dispatching modes and subclass overrides like eager. ([#196055](https://github.com/pytorch/pytorch/pull/196055), @ezyang)
- Fixes compiled graphs that inlined a TorchFunctionMode running the mode a second time, which gave wrong results. ([#196056](https://github.com/pytorch/pytorch/pull/196056), @ezyang)
- Dynamo now raises the same TypeError as eager when a traced __init__ returns a non-None value, instead of silently succeeding. ([#198604](https://github.com/pytorch/pytorch/pull/198604), @hknsahin97-coder)
- Installed precompile artifacts now refuse recompiles with their own callback instead of toggling the process-global fail_on_recompile stance, which broke concurrent torch.compile calls in other threads. ([#198557](https://github.com/pytorch/pytorch/pull/198557), @bobrenjc93)
- Dynamo can now trace calls to a polyfilled function's __wrapped__ or __torch_dynamo_polyfill__ attributes when they are ordinary Python functions. ([#200361](https://github.com/pytorch/pytorch/pull/200361), @XuehaiPan)
- Schema-mismatch errors for custom ops now show list/tuple element types (for example SymInt), hinting that the argument should be declared SymInt[]. ([#199351](https://github.com/pytorch/pytorch/pull/199351), @kostasrigatos)
- Dynamo now handles inherited dict.fromkeys on dict subclasses, building the subclass instead of a plain dict. ([#199358](https://github.com/pytorch/pytorch/pull/199358), @lalit10)
- Fixes len() on an Enum class that has a member named 'name' failing under torch.compile. ([#199043](https://github.com/pytorch/pytorch/pull/199043), @jayzuccarelli)
- Dynamo now supports issubclass, hashing and hasattr on torch.autograd.Function classes without graph breaks. ([#196058](https://github.com/pytorch/pytorch/pull/196058), @ezyang)
- Adds PrecompileSession.snapshot_artifact(), which turns a caller-driven capture into a saveable precompile artifact behind coverage and guard checks. ([#198216](https://github.com/pytorch/pytorch/pull/198216), @bobrenjc93)
- Cuts per-call guard evaluation overhead by restoring the TorchFunction state in C++ instead of reading it from Python each time. ([#198264](https://github.com/pytorch/pytorch/pull/198264), @bobrenjc93)
- C++ fake tensors are now kept out of code paths that assume a plain real tensor. ([#200136](https://github.com/pytorch/pytorch/pull/200136), @liangel-02)
- Dynamo, Inductor and export picklers now serialize C++ fake tensors by metadata rather than as real tensors. ([#200130](https://github.com/pytorch/pytorch/pull/200130), @liangel-02)
- Dynamo's ExtraState C++ API is now keyed on the code object to avoid dangling pointers across the compile callback. ([#200284](https://github.com/pytorch/pytorch/pull/200284), @alexmalyshev)
- Adds a tp_getset implementation for Dynamo's bound builtin method variable. ([#199880](https://github.com/pytorch/pytorch/pull/199880), @guilhermeleobas)
- Fixes a BytesWarning under python -bb on Python 3.10 when resolving a code object's source for precompile. ([#198528](https://github.com/pytorch/pytorch/pull/198528), @bobrenjc93)
- Dynamo's explicit classmethod_descriptor __get__ now validates the owner and treats owner=None like CPython. ([#199247](https://github.com/pytorch/pytorch/pull/199247), @kvnloo)
- Adds the Fake dispatch key to various places as part of C++ fake tensor work. ([#197175](https://github.com/pytorch/pytorch/pull/197175), @liangel-02)
- Dynamo can now trace types.DynamicClassAttribute objects created inside a compiled class body instead of graph breaking. ([#199260](https://github.com/pytorch/pytorch/pull/199260), @kvnloo)
- Fixed assertSequenceEqual and assertMultiLineEqual in the Dynamo test case so equal sequences of different types compare correctly. ([#200295](https://github.com/pytorch/pytorch/pull/200295), @Flamefire)
- Test modifications in preparation for C++ fake tensors. ([#191798](https://github.com/pytorch/pytorch/pull/191798), @liangel-02)
- Review cleanups for PrecompileSession: type annotations and test restructuring. ([#199883](https://github.com/pytorch/pytorch/pull/199883), @bobrenjc93)
- Marked unused function parameters in dynamo, mps and nativert C++ code to silence clang-tidy warnings. ([#199464](https://github.com/pytorch/pytorch/pull/199464), @cyyever)
- Reverted the pruning of unused view ops from proxy tensor traces after it broke internal tests. (`99019960277`, PyTorch MergeBot)

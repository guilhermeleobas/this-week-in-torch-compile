Every torch.compile commit that landed between 2026-10-18 and 2026-10-25, including the ones the [issue]({{< relref "/posts/2026-10-25-this-week-in-torch-compile" >}}) only counted.

## Dynamo commits
- Dynamo now infers torch.full's dtype from a Tensor scalar fill value the way eager does, instead of defaulting to float. ([#199433](https://github.com/pytorch/pytorch/pull/199433), @haojiang01)
- Precompile now records frames Dynamo fell back to eager on, so a loaded artifact runs them eagerly instead of refusing the call. ([#201314](https://github.com/pytorch/pytorch/pull/201314), @bobrenjc93)
- Reduces the cost of Dynamo's autocast state guard by cutting thread-local storage lookups. ([#200299](https://github.com/pytorch/pytorch/pull/200299), @benjaminglass1)
- Dynamo can now trace bytearray.rindex, including start/end arguments and error behavior. ([#201363](https://github.com/pytorch/pytorch/pull/201363), @stefanind)
- Exceptions raised while Dynamo traces a class definition now reach the traced program's try/except instead of escaping the compiled region. ([#195626](https://github.com/pytorch/pytorch/pull/195626), @gabrielfruet)
- Dynamo's default repr and str for traced objects now follow CPython's object_repr with a placeholder address instead of baking one instance's address into reused graphs. ([#200001](https://github.com/pytorch/pytorch/pull/200001), @guilhermeleobas)
- Dynamo guards on a DistributedDataParallel module using a non-default process group can now be serialized, so precompile no longer bypasses those frames. ([#201319](https://github.com/pytorch/pytorch/pull/201319), @bobrenjc93)
- Precompile artifacts now keep identity guards on objects like typing.List that pickle as references to themselves, instead of reporting them as risky drops. ([#201315](https://github.com/pytorch/pytorch/pull/201315), @bobrenjc93)
- Shaves a bit more warm-cache overhead from Dynamo's get_backend by using a cheaper attribute lookup. ([#200300](https://github.com/pytorch/pytorch/pull/200300), @benjaminglass1)
- Moves repr cycle detection into each container's tp_repr in Dynamo, fixing wrong placeholders for self-referential list and dict subclasses. ([#200003](https://github.com/pytorch/pytorch/pull/200003), @guilhermeleobas)
- Dynamo's cache entry getters now return copies, avoiding dangling references after torch._dynamo.reset(). ([#200780](https://github.com/pytorch/pytorch/pull/200780), @alexmalyshev)
- Fixes PyTreeSpec string representations in Dynamo for nested custom nodes so they match native optree. ([#200529](https://github.com/pytorch/pytorch/pull/200529), @XuehaiPan)
- Test-only: classifies Dynamo function tests by hardware and moves accelerator tests into device-instantiated classes. ([#193120](https://github.com/pytorch/pytorch/pull/193120), @taochong123456)
- Test-only: fixes an activation checkpointing test that failed when the FX graph cache was warm. ([#193187](https://github.com/pytorch/pytorch/pull/193187), @pponikox)
- Test-only: classifies fx graph runnable tests by hardware. ([#193271](https://github.com/pytorch/pytorch/pull/193271), @taochong123456)
- Test-only: classifies guard serialization tests by hardware. ([#192981](https://github.com/pytorch/pytorch/pull/192981), @taochong123456)
- Test-only: classifies Dynamo error message tests by hardware. ([#192790](https://github.com/pytorch/pytorch/pull/192790), @taochong123456)
- Test-only: classifies getitem tests by hardware. ([#193071](https://github.com/pytorch/pytorch/pull/193071), @taochong123456)
- Test-only: skips linalg.inv repro tests when PyTorch is built without LAPACK. ([#200000](https://github.com/pytorch/pytorch/pull/200000), @guilhermeleobas)

## Inductor commits
- Inductor's generated Python wrapper now defines Triton kernels as ordinary module-level functions by default, making the output readable and editable instead of burying kernels in string literals. ([#200502](https://github.com/pytorch/pytorch/pull/200502), @bobrenjc93)
- Fixes a NameError in generated code when a user Triton kernel receives a NamedTuple constexpr argument whose type was missing from the generated namespace. ([#192531](https://github.com/pytorch/pytorch/pull/192531), @sankalpsthakur)
- The compiled binary_cross_entropy now raises on out-of-range inputs like eager does, instead of silently computing. ([#200512](https://github.com/pytorch/pytorch/pull/200512), @KarhouTam)
- Inductor now keeps reset_to_zero and restore_value when rebuilding a user Triton Autotuner, fixing wrong gradients with autotuned kernels. ([#200358](https://github.com/pytorch/pytorch/pull/200358), @eshoyuan)
- Fixes max-autotune benchmark inputs for sliced views whose as_strided offset is rebased to a negative value. ([#200911](https://github.com/pytorch/pytorch/pull/200911), @KarhouTam)
- Fixes wrong results with triton.multi_kernel=1 where a subgraph's kernel names collided with and shadowed the parent's. ([#200214](https://github.com/pytorch/pytorch/pull/200214), @jananisriram)
- Fixes wrong results on MPS when a reduction is fused with index_add or scatter_add, where every thread added the value and scaled the result. ([#201460](https://github.com/pytorch/pytorch/pull/201460), @indrajeetapache)
- Fixes a device-memory leak in AOTInductor GPU wrappers where fallback kernel codegen created tensor handles that were never freed on every forward. ([#201267](https://github.com/pytorch/pytorch/pull/201267), @aaronenyeshi)
- Fixes a compile crash when a prologue fused into a Triton matmul contains a float16 or bfloat16 rounding cast. ([#201029](https://github.com/pytorch/pytorch/pull/201029), @shoumikhin)
- Fixes flex attention decoding so the safe-boundary setting is computed from each config's own BLOCK_M, which previously failed when BLOCK_M was pinned to a non-default value. ([#201328](https://github.com/pytorch/pytorch/pull/201328), @felipemello1)
- Adds differentiable functional collectives for reduce, gather and scatter, with autograd and Inductor lowerings, enabling migration off torch.distributed.nn.functional. ([#200881](https://github.com/pytorch/pytorch/pull/200881), @d4l3k)
- Adds the special_legendre_polynomial_p operator on Apple's MPS backend. ([#195226](https://github.com/pytorch/pytorch/pull/195226), @BenjaminDEMAILLE)
- AOTInductor now prefers shared memory over L1 cache for Triton kernels using more than 48 KB, matching torch.compile's speed. ([#201488](https://github.com/pytorch/pytorch/pull/201488), @edmundshieh)
- Inductor rejects Triton kernels whose tensor memory (Blackwell GPUs) exceeds the budget before static loading instead of failing later. ([#201773](https://github.com/pytorch/pytorch/pull/201773), @stashuk-olek)
- Generated Inductor wrappers now include only the imports and bindings they actually use, removing about 30 lines of noise from each module. ([#200518](https://github.com/pytorch/pytorch/pull/200518), @bobrenjc93)
- Fixes precision of compiled expm1 and log1p near zero on MPS so they match eager. ([#201580](https://github.com/pytorch/pytorch/pull/201580), @jzluo)
- Speeds up Inductor's fusion pass for large foreach ops by computing reduction flags incrementally, cutting 42s to 30s on a 1,961-parameter optimizer step. ([#201092](https://github.com/pytorch/pytorch/pull/201092), @anijain2305)
- Stops Inductor applying NVIDIA-specific reduction thresholds on ROCm GPUs whose architecture version number happens to look like a newer NVIDIA one. ([#198195](https://github.com/pytorch/pytorch/pull/198195), @lstojilj-amd)
- Flattens aligned memory-pool size expressions in Inductor codegen to prevent RecursionError on graphs with many allocations. ([#201510](https://github.com/pytorch/pytorch/pull/201510), @minjang)
- Fixes AOTInductor models failing to load on macOS when the constants C++ build path is used, due to a doubled symbol underscore. ([#201698](https://github.com/pytorch/pytorch/pull/201698), @desertfire)
- Fixes a memory leak where Inductor's static launcher never freed loaded XPU kernels, and cleans up handles when loading fails. ([#200890](https://github.com/pytorch/pytorch/pull/200890), @etaf)
- On AMD GPUs, constant pointer-range hints are now kept in final compilation and sized by backing storage, so shipped kernels match benchmarked speed. ([#201282](https://github.com/pytorch/pytorch/pull/201282), @warrendeng)
- Inductor now always forwards AMD compiler options (waves_per_eu, kpack, matrix_instr_nonkdim) to Triton instead of dropping them when the TLX list is empty. ([#201352](https://github.com/pytorch/pytorch/pull/201352), @warrendeng)
- The FX wrapper backend now preserves dtype-changing views such as FP8 reinterpretations instead of inheriting the backing buffer's dtype. ([#201469](https://github.com/pytorch/pytorch/pull/201469), @marvin-kim)
- Flex decoding now checks BLOCK_M divided by GQA heads against the sparse Q block size and caps the default BLOCK_M, fixing failures with pinned block sizes. ([#201329](https://github.com/pytorch/pytorch/pull/201329), @felipemello1)
- Moves std_mean to a Metal kernel on MPS, giving roughly 2.6-4x speedups with no regressions. ([#201310](https://github.com/pytorch/pytorch/pull/201310), @Isalia20)
- Adds torch::stable::add to the stable C++ ABI, gated on a new TORCH_VERSION_2_16_0. ([#196762](https://github.com/pytorch/pytorch/pull/196762), @adabeyta)
- Fixes a race in AOTI package loading where concurrent loads mutated a shared static JSON object and could corrupt the heap. ([#201261](https://github.com/pytorch/pytorch/pull/201261), @splhack)
- Fixes RNG ops (rand, randn, randint, dropout) failing to compile under compile_on_one_rank. ([#196152](https://github.com/pytorch/pytorch/pull/196152), @aorenste)
- Makes the softshrink decompositions match eager bitwise on NaN and signed zeros per backend. ([#200802](https://github.com/pytorch/pytorch/pull/200802), @ezyang)
- Clears the candidate_tilings cache after scheduler codegen so past compiles' graphs and frozen weights are no longer kept alive. ([#200216](https://github.com/pytorch/pytorch/pull/200216), @ezyang)
- Inductor now scans each subgraph's generated code separately so unused imports from branch kernels are dropped from the wrapper preamble. ([#200519](https://github.com/pytorch/pytorch/pull/200519), @bobrenjc93)
- Inductor-generated wrappers no longer include the AsyncCompile setup when the module compiles no kernels. ([#200520](https://github.com/pytorch/pytorch/pull/200520), @bobrenjc93)
- The batch_linear_lhs fusion on XPU now rejects zero-width weights and malformed biases that would change results when concatenated. ([#201532](https://github.com/pytorch/pytorch/pull/201532), @xuhancn)
- Inductor's Python wrapper now writes its preamble imports and bindings one line at a time, preparing for selective emission. ([#200517](https://github.com/pytorch/pytorch/pull/200517), @bobrenjc93)
- Inductor's device table now recognizes the GB300 Max-Q GPU name so it gets correct TFLOPS estimates instead of a roughly 5.7x underestimate. ([#199952](https://github.com/pytorch/pytorch/pull/199952), @danpog)
- Module-level Triton kernels now compile from the decoded source so kernels with backslashes (such as inline asm) behave the same as in string form. ([#200500](https://github.com/pytorch/pytorch/pull/200500), @bobrenjc93)
- Emitted Python from export_python and precompile is now loaded from a cache file, which module-level Triton kernels require. ([#200501](https://github.com/pytorch/pytorch/pull/200501), @bobrenjc93)
- Raises the minimum Python recursion limit during compile_fx to 3000 to avoid RecursionError on large AOTInductor graphs. ([#201484](https://github.com/pytorch/pytorch/pull/201484), @shawnxu26)
- Adds Radeon PRO W7900 compute and bandwidth figures to Inductor's device table instead of falling back to generic formulas. ([#198483](https://github.com/pytorch/pytorch/pull/198483), @lstojilj-amd)

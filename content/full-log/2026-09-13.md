## Dynamo commits
- Fixed a Dynamo bug where compiling code after loading a previously saved compiled package could crash due to a global variable name collision, by minting names guaranteed unique to the target module. ([#196822](https://github.com/pytorch/pytorch/pull/196822), @bobrenjc93)
- Dynamo no longer crashes when a graph-traced object calls a method decorated with torch.no_grad, torch.enable_grad, dual_level, or inference_mode. ([#195413](https://github.com/pytorch/pytorch/pull/195413), @aperson30)
- Switched an internal tracing check in nn.Module's forward call path to a lighter-weight API, giving roughly 15% faster module call overhead when JIT tracing. ([#196236](https://github.com/pytorch/pytorch/pull/196236), @benediktjohannes)

- Dynamo's precompile cache now discards only the specific guard variant that failed to serialize instead of throwing away all working recompiles for that code object. ([#196505](https://github.com/pytorch/pytorch/pull/196505), @bobrenjc93)
- Adds a declarative 'implies' mechanism to PyTorch's config system so selecting one config mode can automatically force related settings. ([#196663](https://github.com/pytorch/pytorch/pull/196663), @karthickai)
- Dynamo now surfaces more genuine user errors directly instead of masking them as graph breaks. ([#196432](https://github.com/pytorch/pytorch/pull/196432), @hameerabbasi)

- Fixed a Dynamo bug where the FP64 upcast used for softmax/log-softmax debugging repros left a stale half_to_float flag, breaking output overload argument matching. ([#194595](https://github.com/pytorch/pytorch/pull/194595), @mengph)
- Fixes Dynamo to correctly resolve closure sources for nested torch.compile-decorated methods, preventing wrong guard evaluation. ([#184977](https://github.com/pytorch/pytorch/pull/184977), @jansel)

- Unpicklable guarded values during precompilation now surface as a clear PackageError instead of an internal error. ([#196470](https://github.com/pytorch/pytorch/pull/196470), @bobrenjc93)
- Fixes Dynamo's guard-state pickling to correctly rebuild closure cells that were never assigned a value. ([#196472](https://github.com/pytorch/pytorch/pull/196472), @bobrenjc93)
- Dynamo's guard pickler now handles bound methods built with types.MethodType where the method can't be found via normal attribute lookup. ([#196473](https://github.com/pytorch/pytorch/pull/196473), @bobrenjc93)
- Dynamo's guard pickler can now rebuild functions wrapped with functools.wraps by reconstructing them from their code object instead of failing to resolve by name. ([#196474](https://github.com/pytorch/pytorch/pull/196474), @bobrenjc93)
- Guard pickling now snapshots a rebuilt function's global variables when a guard depends on them, fixing incorrect behavior for functools.wraps-wrapped functions. ([#196478](https://github.com/pytorch/pytorch/pull/196478), @bobrenjc93)
- Dynamo now correctly routes custom PrivateUse1 (out-of-tree accelerator) tensor classes through its in-graph class handling. ([#195432](https://github.com/pytorch/pytorch/pull/195432), @Beaver2323)
- Fixes function rebuilding during pickling to use the module that actually defined the function, not the misleading __module__ copied by functools.wraps. ([#196684](https://github.com/pytorch/pytorch/pull/196684), @bobrenjc93)
- AOT compile's pickler is rebuilt on the shared base class, fixing crashes when saving compiled functions that close over functools.wraps-decorated helpers. ([#196685](https://github.com/pytorch/pytorch/pull/196685), @bobrenjc93)

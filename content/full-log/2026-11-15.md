Every torch.compile commit that landed between 2026-11-08 and 2026-11-15, including the ones the [issue]({{< relref "/posts/2026-11-15-this-week-in-torch-compile" >}}) only counted.

## Dynamo commits
- Removes the deprecated public TorchScript APIs (torch.jit.script, trace, load, save, freeze, and others) and makes torch.load reject TorchScript archives. ([#203621](https://github.com/pytorch/pytorch/pull/203621), @janeyx99)
- Dynamo now guards on a dictionary's insertion order, runtime type, and length wherever user code can observe them, so a cached graph that depends on those facts is no longer reused when they change. ([#200601](https://github.com/pytorch/pytorch/pull/200601), @XuehaiPan)
- Fixes wrong results when a compiled function that mutates an input is later called with overlapping views; new AOTAutograd guards trigger a recompile instead. ([#185891](https://github.com/pytorch/pytorch/pull/185891), @yinli-systems)
- Fixes Dynamo silently ignoring an autograd.Function's custom jvp under forward-mode AD and returning wrong tangents; it now graph-breaks or recompiles instead. ([#193277](https://github.com/pytorch/pytorch/pull/193277), @RyanL2)
- Loading a precompiled or AOT compile package now checks GPU architecture instead of GPU name, so packages built on one variant (for example GB300) load on a same-silicon variant (GB300 Max-Q). ([#204527](https://github.com/pytorch/pytorch/pull/204527), @bobrenjc93)
- Fixes stale graph reuse with caching_precompile=True, which dropped the closure guard (CLOSURE_MATCH) so rebinding a global function did not trigger a recompile. ([#204502](https://github.com/pytorch/pytorch/pull/204502), @williamwen42)
- Fixes stale results when d[key] raises KeyError inside a compiled function; Dynamo now guards on key membership, so a later call with the key present recompiles. ([#201414](https://github.com/pytorch/pytorch/pull/201414), @Sukhshum2628)
- Fixes Dynamo's itertools.cycle polyfill so a stateful iterable is iterated only once, matching CPython and eager results. ([#201608](https://github.com/pytorch/pytorch/pull/201608), @mottopanikeiku)
- Fixes a circular import between the AOTAutograd runtime wrappers and Dynamo that could leave Dynamo half-initialized and make later torch.compile calls fail. ([#204231](https://github.com/pytorch/pytorch/pull/204231), @LittlePyx)
- Len() on a 0-dimensional tensor under torch.compile now raises TypeError like eager mode does, instead of leaking an internal IndexError that failed compilation. ([#203515](https://github.com/pytorch/pytorch/pull/203515), @vuvinh08)
- Fixes hasattr and getattr-with-default on tensor wrapper subclass methods under Dynamo, which previously took the 'attribute missing' branch. ([#203394](https://github.com/pytorch/pytorch/pull/203394), @egeboy35)
- On Python 3.13 and 3.14, Dynamo restores missing exception-table entries for comprehension filter jumps, fixing graph-break resumes that skipped re-entering a with block or hit an AssertionError. ([#204236](https://github.com/pytorch/pytorch/pull/204236), @SubbaraoGarlapati)
- Dynamo can now trace item and slice assignment and deletion on bytearrays created inside the compiled function. ([#201964](https://github.com/pytorch/pytorch/pull/201964), @losewayy)
- Dynamo now normalizes custom __hash__ results the way CPython does (mapping -1 to -2 and reducing out-of-range integers). ([#201180](https://github.com/pytorch/pytorch/pull/201180), @riccardofelluga)
- Dynamo can now trace bytearray.join over lists, tuples, and generators of bytes or bytearray items. ([#201965](https://github.com/pytorch/pytorch/pull/201965), @losewayy)
- Speeds up Dynamo tracing by caching source locations and config reads on the per-instruction step and push path. ([#204142](https://github.com/pytorch/pytorch/pull/204142), @guilhermeleobas)
- Dynamo now records user stack traces for side effects only when a log or trace will read them, saving about 6% of tracing time on mutation-heavy code. ([#204148](https://github.com/pytorch/pytorch/pull/204148), @guilhermeleobas)
- Trims per-instruction work in Dynamo's step() and popn(), making loop-heavy tracing about 1.1x faster. ([#204150](https://github.com/pytorch/pytorch/pull/204150), @guilhermeleobas)
- Adds torch._C._has_storage_data, a reliable way to check whether a tensor (including wrapper subclasses) owns real data, and uses it in deepcopy and pickling. ([#203963](https://github.com/pytorch/pytorch/pull/203963), @aelavender)
- Dynamo now passes format strings for the print higher-order op as graph inputs (a basic symbolic string), so changing the string no longer forces a recompile. ([#201483](https://github.com/pytorch/pytorch/pull/201483), @rtimpe)
- Dynamo can now trace float subclasses on Python 3.11. ([#203642](https://github.com/pytorch/pytorch/pull/203642), @rtimpe)
- Under nested graph breaks, a graph break inside a loop now propagates to a caller frame outside the loop, instead of piling up resume frames until recompile or recursion limits are hit. ([#202153](https://github.com/pytorch/pytorch/pull/202153), @williamwen42)
- Dynamo now guards the class metadata that a __getattr__ fallback depends on before inlining it, so changes trigger a recompile instead of returning stale results. ([#202154](https://github.com/pytorch/pytorch/pull/202154), @williamwen42)
- Fixes a stack underflow on Python 3.11 when a nested graph break happens inside a getter reached through a method call (LOAD_METHOD). ([#202155](https://github.com/pytorch/pytorch/pull/202155), @williamwen42)
- Turns on nested graph breaks (NGB) across the PyTorch test suite, as a step before making them the default for open-source users. ([#198949](https://github.com/pytorch/pytorch/pull/198949), @williamwen42)
- Nested compile regions can now set combo_kernels and max_autotune_pointwise in their per-region Inductor config. ([#203530](https://github.com/pytorch/pytorch/pull/203530), @Microve)
- Adds a native guard for OrderedDict insertion order that checks it without running user callbacks. ([#203342](https://github.com/pytorch/pytorch/pull/203342), @XuehaiPan)
- Dynamo now models gi_frame and its f_back for generators that are not running, matching CPython's behavior. ([#199787](https://github.com/pytorch/pytorch/pull/199787), @weicheng-hsu)
- Dynamo now installs guards on the operands of lazily computed constants when they are reconstructed. ([#204692](https://github.com/pytorch/pytorch/pull/204692), @rtimpe)
- Complex constructors built from real inputs (view_as_complex, complex, polar) now go through the ComplexTensor decomposition instead of bypassing it. ([#204779](https://github.com/pytorch/pytorch/pull/204779), @SakshamKapoor2911)
- Disables nested graph breaks (NGB) inside PyTorch's testing helper modules to reduce test compile time. ([#204863](https://github.com/pytorch/pytorch/pull/204863), @williamwen42)
- Replaces several per-type call_obj_hasattr implementations in Dynamo with one centralized hasattr. ([#197322](https://github.com/pytorch/pytorch/pull/197322), @guilhermeleobas)
- Dynamo's LazyCache now checks type(value) instead of calling isinstance, so it no longer runs a user object's custom __class__ property during tracing. ([#204124](https://github.com/pytorch/pytorch/pull/204124), @arnavdesai2003)

## Inductor commits
- AOTInductor models compiled with aot_inductor.cudagraphs=True can now run as CUDA graphs through a new C API and a Python run_with_lazy_cuda_graphs method on loaded packages. ([#202231](https://github.com/pytorch/pytorch/pull/202231), @desertfire)
- On CUDA, Inductor now replaces small topk calls (k up to 16 over rows of at most 1024 elements) with fused rounds of argmax, which greatly speeds up mixture-of-experts routers such as DeepSeek-V3's. ([#200740](https://github.com/pytorch/pytorch/pull/200740), @anijain2305)
- Fixes an unsound dynamic-shapes guard where float-valued symbolic expressions were truncated to integers, producing guards that failed on the very inputs they were built from. ([#202324](https://github.com/pytorch/pytorch/pull/202324), @laithsakka)
- Fixes wrong results from compiled resize_/resize_as_ on padded, permuted, or sliced inputs, which Inductor read as dense memory and ignored their strides. ([#204633](https://github.com/pytorch/pytorch/pull/204633), @nandesuka)
- Fixes a memory leak where AOTInductor model .so files could never be unloaded on long-lived server threads, because of a thread-local error string with a non-trivial destructor. ([#204491](https://github.com/pytorch/pytorch/pull/204491), @aaronenyeshi)
- Fixes Inductor's FX wrapper launching user-defined Triton kernels with the wrong grid or shifted arguments, caused by compile-time constant (constexpr) arguments being restored before the grid was read. ([#204567](https://github.com/pytorch/pytorch/pull/204567), @zlin888)
- Inductor now builds host-side TMA (Tensor Memory Accelerator) descriptors from dynamic sizes read at launch, avoiding per-block on-device descriptor creation and speeding up GEMM templates with dynamic shapes on H100. ([#202612](https://github.com/pytorch/pytorch/pull/202612), @htyu)
- Fixes Inductor's no-op removal pass collapsing two distinct graph outputs into the same tensor. ([#203433](https://github.com/pytorch/pytorch/pull/203433), @nirali25parekh)
- Adds public F.quantize_tensor and F.quantize_tensor_dual APIs, starting with MXFP8 quantization backed by CuTe DSL kernels. ([#199022](https://github.com/pytorch/pytorch/pull/199022), @vkuzo)
- Adds a disallow_implicit_grad_accumulation flag to .backward() that raises an error whenever backward would silently sum gradients from a tensor used more than once. ([#203413](https://github.com/pytorch/pytorch/pull/203413), @soulitzer)
- FlexAttention now clamps out-of-range captured-buffer indices instead of wrapping them with a modulo, which is much faster for sequence lengths that are not block multiples and for dynamic shapes. ([#204156](https://github.com/pytorch/pytorch/pull/204156), @drisspg)
- Enabling the profiler no longer forces Inductor kernels onto the slow Python launch path, so profiles stop showing CPU launch overhead that does not exist in normal runs. ([#203702](https://github.com/pytorch/pytorch/pull/203702), @sanrise)
- Fixes an AssertionError with mode='reduce-overhead' when the forward runs as a CUDA graph but the backward cannot; the backward now looks up the CUDA graph tree manager only when it runs. ([#202857](https://github.com/pytorch/pytorch/pull/202857), @bobrenjc93)
- Inductor's opt-in NaN/Inf checks (the nan_asserts option) now report the Triton kernel name as well as the buffer name in their failure messages. ([#204043](https://github.com/pytorch/pytorch/pull/204043), @guyko)
- Adds capture_region_inputs for regional AOTInductor (ahead-of-time compiled regions), which runs one eager forward pass and records the inputs of every call to each marked module. ([#201090](https://github.com/pytorch/pytorch/pull/201090), @ZixinYang)
- Fixes compiled in-place foreach ops on complex tensors, which failed because their fallback did not mutate the inputs correctly. ([#201839](https://github.com/pytorch/pytorch/pull/201839), @khushi-411)
- Adds a general einsum-based decomposition for aten._trilinear (used by nn.Bilinear), so compiled code can lower it to batched matmuls. ([#202958](https://github.com/pytorch/pytorch/pull/202958), @khushi-411)
- Fixes CUDA bf16/fp16 scalar addition and subtraction under emulate_precision_casts, which rounded the scalar too early and did not match eager results. ([#203999](https://github.com/pytorch/pytorch/pull/203999), @warrendeng)
- Fixes an Inductor crash in assert_alignment when multi-head attention with need_weights=False returns None for its attention weights. ([#202041](https://github.com/pytorch/pytorch/pull/202041), @khushi-411)
- Inductor's C++ wrapper mode can now generate code for custom ops that return an optional list of tensors (Tensor[]?). ([#204264](https://github.com/pytorch/pytorch/pull/204264), @jiaxingh14)
- On ROCm, Inductor now uses AMD's Origami performance model to pick FlexAttention tile configs on gfx950, which cuts autotuning time and improves the chosen kernels. ([#196714](https://github.com/pytorch/pytorch/pull/196714), @nithinsubbiah)
- Inductor's static CUDA launcher and AOTInductor can now launch Triton kernels that use more shared memory than the per-block opt-in limit (oversized shared memory mode) on sm_107. ([#199309](https://github.com/pytorch/pytorch/pull/199309), @mattteochen)
- Fixes override_cudagraphs being silently undone when torch.compile options set triton.cudagraphs=False. ([#202419](https://github.com/pytorch/pytorch/pull/202419), @sijiaw-meta)
